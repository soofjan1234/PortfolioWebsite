# 人物 3D 主页改版设计

目标是在现有网站内实现自己的 3D 人物主页：人物外观来自 `public/avator.png`，场景构图、滚动运镜、景深、眼球互动与作品展示参照 About Sen。字体、配色、文案与作品使用自己的设计和内容；Tech Hub 位于倒数第二个内容栏目，作品作为最后一个内容栏目，其后保留联系页脚。

本稿描述已确认的主页改造方案。人物模型已由用户验收；第一轮主页虽然通过功能浏览检查，但左右分栏与浅色卡片偏离参考站，用户已明确要求纠正。进度集中维护在 [status.md](status.md)，网页证据见 [主页验收记录](home-verification.md)。

## 参考站构图修正

目标：落实已确认的构图与交互复刻。范围仍是首屏、履历、Tech Hub、末尾作品，不更换已验收人物、不增加新路由。

改动方案：全视口人物背景配绿色渐变和颗粒；简介在人物胸前居中，细边框与角标替代厚导航；右侧时间线叠加渐暗与磨砂背景，履历之间推进面部特写和自己的贴纸；作品与 Tech Hub 使用相连的深色全高展板，Tech Hub 从视口右侧入场。手机保持全屏人物及原生横滑，加载失败继续显示静态人物。

最小契约：输入真实滚动位置、视口高度和首个横向栏目起点，输出首屏淡出/模糊、履历磨砂显隐和作品压暗进度；镜头仍为 24 fps、每段 50 帧，前后各 35% 停顿区间。反向滚动必须恢复同一帧和叠层状态；六个项目、三类共 63 篇文章及独立路由继续可访问。

验证标准：同尺寸对照原站首屏居中构图、右侧履历、Tech Hub 从右侧入场与末尾作品；检查桌面、手机横竖屏、返回首屏、文章弹窗及降级。功能测试通过不能代替视觉验收。

## 首帧与响应式修复（2026-10-04 已确认）

目标与范围：修复人物加载时悬浮落位、低视口联系弹窗裁切、窄屏栏目标题与操作区拥挤；沿用现有人物、内容与滚动结构。

最小契约：输入当前滚动帧与设备策略，首次绘制直接使用目标相机姿态，绘制成功后才发布 ready；后续帧继续按真实时间阻尼。静态图由同一场景的稳定首帧生成，按设备策略选择，并保持相同的纵向构图。联系窗口在视口内提供独立滚动内容和始终可见的关闭按钮；窄屏栏目标题与按钮流式排列，避让顶部导航。

验证标准：首帧与稳定帧在无输入时相机位置一致；桌面、窄屏、页面中段初始化均可用；320px 窄屏标题与操作不重叠，844×390 横屏可查看完整二维码并关闭窗口；文章、横轨正反向和原路由继续可用。先观察失败回归，再执行目标测试、相关全量与构建，并保留实际浏览截图。

## 已确认的范围

按钮对齐补充（2026-10-04 用户已确认）：左右翻页与回顶、菜单、Contact 在栏目顶部同排居中。圆形按钮统一 34px、相邻间距 16px，Contact 固定宽 72px；CSS 共享变量计算右侧预留距离。窄屏栏目到达顶部时同样对齐，标题与文章库入口位于按钮下方；不改变原翻页和回顶行为。

右上角导航补充（2026-10-04 用户已确认）：按钮组整体下移约 20px，位于细边框下方；首页滚动超过 120px 后在菜单左侧显示同风格圆形回顶按钮，回到 0px 后隐藏。点击关闭展开菜单并平滑返回顶部，减少动态效果时立即返回；键盘焦点交回菜单按钮。输入为首页路由、滚动位置和动态效果偏好，输出为按钮显隐及滚动行为；其他路由保持原导航。桌面栏目操作区为三按钮导航留出右侧空间，手机检查标题与按钮不重叠。验证覆盖阈值、回顶、减少动态效果、独立路由和桌面/手机布局。

- 人物形象：以现有头像提供身份特征，黑色矩形眼镜、浅色圆领上衣；发色经预览改为黑色，发型保持侧扫与轻微蓬松，减少分块并形成连续体积。五官与表情采用已认可的夸张卡通造型。
- 首屏是自己的卡通人物与简介，向下滚动逐段运镜到履历，最后进入作品与 Tech Hub。
- 复刻参考站的构图方式、镜头叙事、景深、眼球跟随和滚动交互。人物、贴纸、内容、字体、页面配色由自己定义。
- Tech Hub 的 Go、MySQL、Redis 与源码内容保留，改为末尾横向浏览，并保留文章访问能力。
- 不以 NAS 工作台替代人物。多视图参考图用于确认造型，不作为 GLB 或最终网页效果的交付证据。

## 场景与页面如何协作

固定的 3D 画布展示人物；普通 HTML 承载简介、履历、Tech Hub 和末尾作品。页面滚动进度驱动 GLB 的相机时间轴与对焦点，使文字所在阶段和人物特写一致。眼球跟随鼠标单独运行，在触屏设备上维持默认目光。

内容与场景共享一份履历节点定义。履历节点增删时同步更新 GLB 对焦点与镜头区间，不能分别硬编码节点数量。相机动画采用参考站的 24 fps、每个履历节点 50 帧约定；作品段和 Tech Hub 段单独保留镜头停靠位置。

参考站的 MIT 场景代码可以适配到现有 React/Vite 项目，保留许可证与来源说明。保持现有网站和路由入口可访问，不为移植效果而整体重建工程。新增三维加载和后期依赖前核对现有 React、Three.js 与 React Three Fiber 的兼容范围。

## 人物制作路线

建议采用“造型参考图 → 图生 3D 基础模型 → Blender 精修与场景配置 → GLB 导出”。图生 3D 解决初始体积和纹理，Blender 阶段负责轮廓、眼镜、眼球分离、材质、相机与对焦点；不能假设生成模型已经适配参考站。

当前造型参考为 [人物正面 v5](assets/character-front-v5-unified.png)：大眼球、粗眉毛、较大的圆鼻子、哑光材质和轻微不对称表情；黑框眼镜与浅色上衣保持。脸、眼镜、表情和衣服已获认可。发型按用户确认方向改为黑色短发、侧扫刘海与轻微蓬松，以连续形体和少量方向凹槽表现层次；v5 已获用户确认。使用内置 ImageGen 工具；[v5 完整提示词](assets/character-front-v5-unified-prompt.md) 记录局部修改要求。彩色 GLB 已由用户提供；其头发几何仍较细碎，精修阶段需与 v5 比较。旧版四视图暂不作为新版形体的直接依据。

| 路线 | 优点 | 代价与条件 |
| --- | --- | --- |
| 图生 3D 初稿后精修（推荐） | 较快获得接近头像的有机形体和纹理 | 需要可用的三维生成服务；人物结构和细节仍需精修，外观必须验收 |
| Blender 从零制作 | 完全控制网格、眼球、眼镜和镜头 | 需要建模能力和更长的雕刻调整时间，不能以简单几何拼接替代目标质量 |

已通过用户登录的 Meshy 浏览器页面接入建模流程。账号当前显示 100 点；Meshy 6 Lite 一次生成显示 10 点，免费计划支持该版本每月 10 次下载。Meshy 6/7 的下载和多视图等功能受付费权限限制，因此先使用可下载的 Lite 生成一份基础模型，按外观验收决定是否能继续精修，不能将 Lite 初稿等同于参考站的成品质感。上传已获用户许可；购买套餐或额外额度不在当前授权内。

Lite 使用独立正面图输入。灰模与彩色版均保留在 `assets/model/`；几何与贴图分别检查，不能假设换贴图能改变发型。精修环境采用 PyPI 官方 Blender Python 模块 `bpy==4.5.14`，Python 3.11，安装在忽略目录 `.codex-model-tools/`，不依赖本机图形版 Blender。

## 最小模型契约

第一版的后续外观精修采用材质、局部形体和灯光联合调整，专项方案见 [人物质感联合精修设计](design/character-quality.md)。该方案以模型验收页的真实浏览器对照为外观依据，并遵守下述模型契约。

| 项目 | 输入或输出要求 |
| --- | --- |
| 输入 | 当前头像、已确认正面 v5 与自己的基础 GLB；履历节点数 N 与对应内容 |
| 编辑源 | 可继续编辑的 Blender 场景或等价建模源文件，保留材质与动画 |
| 网页输出 | `public/models/me.glb`，模型、材质与必要纹理可完整加载 |
| 形体 | 独立的人物、头发、眼镜和左右眼球；镜头内需要的颈部与肩部几何完整 |
| 眼球 | `eye-left`、`eye-right`，各自的旋转中心在眼球中心；转动不牵动眼镜和头部 |
| 相机 | 至少一台透视相机，包含 `CameraAction` 动画，导出后有有效的位置和旋转轨道 |
| 履历焦点 | `focus-start`、`focus-1` 至 `focus-N`，顺序与履历节点一致 |
| 末尾焦点 | `focus-works`；Tech Hub 使用新增的 `focus-tech-hub`，网页端明确接入该扩展点 |
| 坐标与资源 | 保持 glTF 的 Y 轴向上约定；纹理可解析，不依赖制作机器上的本地路径 |

人物贴纸在造型确定后使用自己的内容制作。只对场景镜头内可见区域进行必要制作与验证；若后续需要全身、表情变化或身体动作，需更新模型范围和契约。

## 滚动与失败恢复

- 简介与履历：纵向滚动控制运镜，反向滚动可以回到对应镜头，不产生无法恢复的动画状态。
- 作品与 Tech Hub：桌面端进入栏目后，纵向滚动进度推进横向轨道；到达轨道末尾后正常离开，反向滚动也能退出。移动端以直接左右滑动为主，并提供可操作的文章入口。
- 加载阶段：HTML 内容与加载状态先展示，模型准备好后启用场景。模型加载失败、WebGL 不可用或用户减少动态效果时，仍可阅读内容并使用链接。
- 移动端：限制渲染分辨率和昂贵后期效果，关闭鼠标依赖；不能因为降级丢失履历、作品或文章。

## 验证标准

1. 造型验收：正面、侧面、背面一致；黑发、黑框眼镜、浅衣与已确认造型相符，近景中无明显穿插或破损。
2. 模型结构：GLB 可解析，所需节点、材质、相机和 `CameraAction` 全部存在，节点数量与履历定义相符；独立眼球实际可转动。
3. 场景行为：选择固定滚动位置，对照参考站检查首屏、履历特写、作品入场和横向浏览的构图与转换，单独验收自己的外观和内容。
4. 网页行为：桌面和手机可完成完整浏览，横向栏目能进入和退出，链接可操作，减少动态效果及加载失败时保留阅读能力。
5. 工程验证：按“RED → 目标 GREEN → 最终相关全量”执行模型契约和滚动行为检查，最后运行生产构建及相关页面验证。没有真实 GLB 的阶段只报告设计与参考图，不能宣称三维模型已完成。

## 已确认的文章顺序与分类调整（2026-10-04）

目标和范围：履历 → 文章 → 项目 → 联系页脚；首页及完整文章库按实际技术主题归类。用户已确认实施。

最小契约：分类输入为 paths 数组，输出为按来源顺序、按 URL 去重的文章列表；任一来源失败时首页整组报错并支持重试，关闭时取消请求。当前 Go 39 篇、MySQL 15 篇、Redis 9 篇，共 63 篇；没有内容的中间件和其他不显示。导航、首段横移留白与压暗边界随新顺序调整；模型保留原始节点，文章映射 200 帧、项目映射 150 帧，允许反向插值。

验证标准：栏目顺序正确、63 篇链接保留且无重复，聚合失败可重试，桌面和窄屏文章弹窗可访问，独立文章库分类一致。

首页“完整文章库”入口按用户补充要求直达个人掘金文章页 https://juejin.cn/user/4074147977125020/posts，在新标签页打开；站内 /projects 保留为独立文章浏览与加载失败备用入口。Redis 标识展示全名。
