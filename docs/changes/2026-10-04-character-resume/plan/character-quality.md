# 人物质感联合精修实施计划

依据：[人物质感联合精修设计](../design/character-quality.md)。实施顺序为固定基线、皮肤小样、眼部接合、发束整理、整体布光、浏览器验收；设计中的范围与外观标准不在此重复。进度维护在 [主题状态](../status.md)。

以下路径除文档链接外均相对仓库根目录。`assets/model/quality-refinement/` 指本主题资产目录下的精修证据目录。

## 实施入口与冻结契约

保留 `scripts/prepare-character-scene.py` 作为第一版生成入口，新增 `scripts/refine-character-quality.py` 读取第一版编辑源并逐步精修，避免每次实验重新执行区域拆分、眼窝切除与第一版减面。

| 项目 | 本轮约定 |
| --- | --- |
| 输入 | `assets/model/hou-scene-v1.blend`、第一版备份 `assets/model/quality-refinement/baseline.glb`、`src/data/character-scene.json`；原始彩色模型供几何与 UV 对照 |
| 候选输出 | `public/models/me-quality-candidate.glb`、`assets/model/quality-refinement/hou-quality-candidate.blend` |
| 脚本入口 | `.codex-model-tools/bin/python scripts/refine-character-quality.py --stage=skin\|eyes\|hair\|final`；阶段按顺序累计执行，每次从第一版源重新生成，失败退出码非零 |
| 报告 | 阶段、输入/输出哈希、材质/网格/纹理数量、尺寸与包体、遮罩覆盖率、首个问题；几何数组和像素数据不写入摘要 |
| 预览入口 | 现有 `assets/model/preview.html` 默认加载交付模型；`?quality=candidate` 从固定白名单加载候选。目光、相机按钮和时间轴保持现有行为 |
| 输出保护 | 导出先写临时文件，模型就绪检查通过后发布到候选路径；失败保留上一份有效候选。验收后才替换交付 GLB |

精修脚本只导出人物、眼球、履历相机及焦点；第一版编辑源中另有离线预览相机和灯具，须排除在网页导出集合之外。沿用现有节点命名、眼球旋转中心与 `CameraAction`，不重新拟合眼球或重建履历轨道。

## 1. 固定可比较的基线

**文件：**现有 `assets/model/preview.html`；新增 `assets/model/quality-refinement/baseline.json` 与基线截图。

1. 记录输入模型与编辑源哈希；保存当前交付 GLB 和预览设置的可恢复基线。
2. 保存桌面正面、侧面、背面和特写。固定视口、设备像素比、镜头、曝光、鼠标目光和景深状态，截图时关闭目光跟随与景深。
3. 修改 `loadModel()` 的模型路径选择，候选参数仅映射固定文件名。验证默认入口仍加载第一版，候选缺失时显示现有失败状态，不能悄悄回退后标记为候选。
4. 将当前皮肤单一、眼部边缘、发束轮廓的问题标在基线记录中，作为视觉 RED。已有结构契约通过时不制造假的结构失败。

**通过条件：**相同设置能再次得到相同构图，基线与候选有可核对的文件身份。依赖：已确认的专项设计。

## 2. 先交付皮肤与脸部特写小样

**文件：**新增 `scripts/refine-character-quality.py`、`scripts/test_refine_character_quality.py`；候选 GLB、编辑源与本阶段证据。

1. 先写失败测试：使用一个包含皮肤、牙齿和眉毛的最小纹理/遮罩样例，要求变色仅作用于皮肤，保护区域保持原值；无效 UV 输入须明确失败。初始失败应来自缺少精修实现。
2. 从第一版编辑源复制头部、衣服和镜框材质，使三者可独立调整。头部仍包含牙齿、眉毛、嘴唇等区域，先用位置、表面朝向和原始底色生成皮肤及保护遮罩，输出正面和侧面的遮罩检查图。
3. 在脸颊、鼻尖与耳朵上建立平滑的暖色渐变，使用 Blender 材质节点与烘焙生成底色和粗糙度贴图；保留原 UV、眉毛、牙齿与口腔颜色。根据近景结果减弱原法线中的不自然凹凸。
4. 优先使用可随 GLB 导出的 PBR 贴图和材质参数。记录底色的 sRGB 与粗糙度/法线的数据色彩设置，核对导出后金属度和粗糙度通道，不能只检查 Blender 画面。
5. 执行 `--stage=skin`，在原布光下对照实际浏览器的正面及特写。此时判断局部肤色、高光和纹理接缝，再进入后续阶段。

**验证：**`.codex-model-tools/bin/python scripts/test_refine_character_quality.py`；候选执行现有 `ready` 校验。通过条件为保护区域不被染色、皮肤有自然层次、无新增接缝，浏览器加载的确是候选。依赖：步骤 1。

## 3. 让眼球与眼窝连续接合

**文件：**精修脚本和上述测试文件；候选模型与眼部特写证据。

1. 在修改前保存眼球中心、默认旋转、头部及眼镜位置。检查眼窝切口的边界环，分别处理左右眼，依据边界与眼球表面的实际距离建立过渡带。用户后续追加增大眼珠间距：球心与缩放仍固定，两侧默认朝向各外偏 0.12 rad。
2. 使用局部顶点权重调整眼睑厚度与边缘，眼角连接头部，眼镜保持原位置；不再次用凸包扩大眼窝。边界无法可靠识别时停止该阶段并报告对象与首个问题。
3. 给现有眼球补可用 UV 与虹膜贴图，增加虹膜放射纹理和边缘深浅；调整眼白颜色及表面响应，保持瞳孔大小和已确认目光特征。
4. 对涉及眼窝选择的新逻辑先补失败用例，验证不连续/错误边界会被拒绝。执行 `--stage=eyes` 后检查中间与上下左右目光，确保眼球不拖动眼镜、转动后不露洞、不出现旧瞳孔。

**验证：**目标 Python 用例、候选 `ready` 校验，以及固定特写与转动截图。通过条件为原有旋转中心和动画契约有效、可见眼睑连续、镜框无遮挡异常。依赖：步骤 2。

## 4. 整理发束体积与表面层次

**文件：**精修脚本；候选模型与正面/侧面/背面证据。

1. 先对照当前发型轮廓及第一版发际线边界，标出尖薄片、过深凹槽和体积断点。按局部区域调形，避免继续对整片头发反复平滑与减面。
2. 把薄片发束整理为较厚、连续的曲面，保留侧扫方向和已确认发际线。若局部调整涉及接缝，先建立与头部接合的底层表面再修改外层发束，并从侧后方检查闭合。
3. 当前 `refine_hair()` 已移除头发 UV；候选阶段重新展开头发 UV，用烘焙后的浅方向纹理与粗糙度变化表达发束层次，主要轮廓由几何承担。
4. 执行 `--stage=hair`，在原布光下旋转检查，再与皮肤及眼部小样组合比较。

**验证：**候选 `ready` 校验，正侧背视角及转动过程检查；细分或烘焙后记录三角形、贴图尺寸和文件大小的变化。不为纯美术参数添加镜像实现的单元测试。通过条件为黑发保持连续体积、没有新增破面和接缝，高光不会碎成亮斑。依赖：步骤 3。

## 5. 在浏览器完成整体布光

**文件：**现有 `assets/model/preview.html` 的环境、主光、补光、轮廓光与渲染设置；整体对照证据。

1. 先完成同布光的材质与形体对照，再调整暖主光、冷轮廓光、环境强度及曝光；背景改为低饱和灰绿。
2. 基于现有 `RoomEnvironment`、阴影和色调映射调试。阴影模糊参数只能用于控制投影过渡，不能替代实际的光照与表面高光调整。
3. 先在关闭景深的特写中看清细节，再检查景深开启后的整体效果；保持移动端分辨率和昂贵后期的现有限制。
4. 使用相同浏览器、视口和镜头记录原版与最终候选的帧耗时或帧率、文件体积和加载表现。出现明显退化时定位具体效果，再降低对应成本。

**通过条件：**肤色暖而不过曝、黑发暗部可辨、冷暖层次明确；浏览器与离线材质方向一致。光照参数通过实际画面对照确定。依赖：步骤 4。

## 6. 最终相关全量与交付

本轮新增自动验证集中在区域保护、输入拒绝与受影响的导出行为；现有交互由模型契约与真实浏览器检查覆盖。只有出现新失败或跨组件风险时扩展相邻测试。

```sh
.codex-model-tools/bin/python scripts/refine-character-quality.py --stage=final
.codex-model-tools/bin/python scripts/test_refine_character_quality.py
node scripts/validate-character-model.mjs public/models/me-quality-candidate.glb --stage=ready --resume-count=2
node --test scripts/validate-character-model.test.mjs
npm run build -- --outDir .codex-model-tools/build-check
git diff --check
```

检查桌面与窄屏的模型加载、四个固定视角、目光开关、相机首尾、反向返回、景深开关及候选加载失败提示，记录浏览器新增错误。最终证据包括同布光对照、整体布光对照、结构报告摘要和候选哈希。

候选通过结构检查并完成外观验收后替换 `public/models/me.glb`，再从默认预览入口检查加载结果和文件哈希；更新模型来源说明、主题状态及实际采用的参数。第一版可恢复基线保留。2026-10-04 用户确认模型收尾，当前正式文件与已验收候选哈希一致，详见 [交付报告](../assets/model/quality-refinement/accepted-report.json)。后续进入总计划阶段三。
