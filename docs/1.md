# 参考

[Logartis](https://logartis.info/) 一类「全屏 3D + 滚动叙事」的站点思路；本项目栈为 **Vite + React + Three.js + @react-three/fiber**，另有 **GSAP**，可直接按下面方式落地。

---

## 采用方案：原地飞 + 背景流（跑步机场景）

核心错觉：**角色在场景中心附近基本不动**（只播放 **Loop 飞行动画** + 可选轻微上下飘），**环境整体朝「身后」方向持续平移**，看起来像一直在往前飞。实现成本通常低于「相机/角色真的沿世界坐标无限飞 + 地形回收」。

1. **角色**：放在视锥体舒适区（常见为原点附近略偏下/偏中），世界坐标几乎不变；用骨骼动画或程序化摆动表现「在飞」。
2. **背景层（分视差更真）**：
   - **远景**：星空、月亮、远处云层 → 速度慢。
   - **中景**：大块云朵、远山轮廓 → 中等速度。
   - **近景**：建筑、地面碎片、近云 → 速度快。
   各层速度比约为 `v远 < v中 < v近`，避免「整张图一起滑」的传送带感。
3. **无限感**：每一类物体用 **2～3 份相同资源** 沿运动轴首尾相接排列；移出相机后方一段距离后，**瞬移**到最前方（与原先「地形条回收」同一数学思想，只是动的是装饰物而不是相机）。
4. **滚动 = 时间轴**：页面纵向很长（例如 `300vh`～`500vh`），`scrollY` 映射到 `0～1` 的**进度**，驱动：背景流速倍率、雾浓度、段落文案显隐等；**不必**用滚动去推相机在世界里的 Z 位移（可选：`progress` 微调背景基础速度或层间对比）。
5. **信息层**：全屏固定 **Canvas（WebGL）在下、HTML 在上**；各段自我介绍用普通 div，根据 `progress` 改 `opacity` / `transform`。

## 页面结构（推荐）

```
┌─────────────────────────────────────┐
│  fixed: inset-0, z-index 低         │  ← R3F <Canvas />
├─────────────────────────────────────┤
│  fixed: inset-0, pointer-events     │  ← 透明层：仅按钮可点
│  none + 子元素 pointer-events-auto │
├─────────────────────────────────────┤
│  document flow: 极高 min-height     │  ← 多个 section，撑出滚动条
│  (例如 min-h-[400vh])               │
└─────────────────────────────────────┘
```

要点：**真正滚动的是下面那层「占位」文档流**，Canvas 始终铺满视口，避免整页跟着 Canvas 一起重排。

---

## 滚动进度

```js
// progress ∈ [0, 1]
const doc = document.documentElement
const max = doc.scrollHeight - window.innerHeight
const progress = max > 0 ? window.scrollY / max : 0
```

在 `scroll` / `resize` 上用 `requestAnimationFrame` 节流一次更新；或把 `progress` 放进 `useRef`，在 R3F 的 `useFrame` 里读最新值，避免每帧 setState。

---

## 相机与角色（本方案下）

- **相机**：多数时间 **固定**或只做 **小幅正弦晃动**（横滚/俯仰一点点），模拟气流；不必沿曲线在世界中长跑。
- **角色**：若 **第三人称**看超人——相机 `lookAt` 角色胸口略上，角色在原点；若 **第一人称**——可不建全身模型，只留披风边缘/手套等近景 mesh + 同样流动的环境（仍属「环境在动」）。
- 背景运动方向与「主观飞行方向」相反：例如主观朝 **-Z** 飞，则各背景组 `position.z += speed * dt`（向 +Z），再在阈值做 **模/回收**。

---

## 背景流与回收（代替「相机飞过地形」）

- 将云朵、星点、楼群等做成 **Group**，每帧 `group.position.z += v * delta`（轴按你场景约定可改为 `x`）。
- 对周期为 `L` 的条带：`z = ((z + offset) % L) - offset`，或对每个子 mesh 判断「若 `z > cameraZ + margin` 则 `z -= segmentLength * N`」。
- **`FogExp2`**：远景糊成一片，弱化重复贴图与接缝。
- **粒子星星**：可用大平面上的点或 instanced mesh，整体与最远景同速或略慢。

---

## 与 React Three Fiber 的配合

- 顶层：`<Canvas gl={{ antialias: true }} dpr={[1, 2]}>`。
- `useFrame` 里更新：**各背景 Group 的 position**、可选相机微动、可选根据 `progressRef` 调整 `v`；**不要**每帧 `setState` 整棵树。
- 角色动画：用 `useFrame` 调 mixer `update(delta)`，或由 glTF 自循环。

可选：**GSAP ScrollTrigger** 把 `scrollY` scrub 到 `progress` ref 或 uniform（例如雾、`v` 倍率）。

---

## 文案与信息露出

- 将 `0～1` 切成多段，例如 `[0,0.2)` 只显示标题，`[0.2,0.4)` 技能……
- 每段用 `opacity = smoothstep(p0, p1, progress)` 或 ScrollTrigger 的 `onUpdate`。
- 注意 **对比度**：暗场景用浅色字 + 轻微 `text-shadow` 或底部渐变遮罩。

---

## 性能与兼容

- 控制 draw call：同层云朵可 **InstancedMesh**；楼群用少量重复单元 + 回收。
- `dpr` 上限 2；移动设备可降低粒子数与模型面数。
- `prefers-reduced-motion`：降低背景速度或改为几乎静止 + 仅文案滚动叙事。

## 实施顺序建议

1. 固定全屏 Canvas + 下方 `400vh` 占位，确认滚动与 `progress` 正确。
2. 相机固定 + 单色雾 + **一层**向后平移的平面/条带 + **回收**，验证「无限滑过」。
3. 加角色占位（方块即可）+ Loop 位移动画；再拆 **远/中/近** 三层速度。
4. 替换为模型与贴图；最后叠 HTML 分区与显隐。

按上述顺序迭代，每一步都可单独验收。
